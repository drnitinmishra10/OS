Process State Transition

During execution, a process moves among different states depending on CPU availability, I/O events, and completion.

TransitionDescription
New → ReadyProcess admitted by OS.
Ready → RunningCPU assigned by scheduler.
Running → WaitingProcess requests I/O.
Waiting → ReadyI/O completes.
Running → ReadyCPU preempted.
Running → TerminatedExecution finishes.

Process Control Block (PCB)

A PCB is the data structure maintained by the operating system to manage each process.

FieldPurpose
Process ID (PID)Unique identifier
Process StateCurrent execution state
Program CounterAddress of next instruction
CPU RegistersSaved register values
Memory InformationBase, limit, page tables
I/O StatusAllocated devices and files
Scheduling InformationPriority, queue pointers
Important: Every process has exactly one PCB while it exists in the system.

Context Switching

Context switching is the process of saving the execution context of the currently running process and restoring the context of another process so CPU execution can continue seamlessly.

Steps

  1. Save CPU registers into current PCB.
  2. Update process state.
  3. Select next ready process.
  4. Load registers from new PCB.
  5. Resume execution.

Dispatcher

The dispatcher transfers CPU control to the process selected by the short-term scheduler.

Context Switching Overhead

  • No useful computation occurs during switching.
  • Frequent switching reduces CPU efficiency.
  • Modern processors use hardware support to reduce overhead.

Real-World Example

When listening to music while editing a document, the operating system rapidly switches between both processes, creating the illusion of simultaneous execution.

Key Points

  • PCB stores complete information about a process.
  • Context switching enables multitasking.
  • The dispatcher performs the CPU handoff.
  • Reducing unnecessary context switches improves performance.
