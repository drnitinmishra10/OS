Context Switching: CPU Management & Process Control

Steps in Context Switching

  1. SAVE CPU Registers Save the execution context (EAX, EBX, SP, PC, etc.) into the current Process Control Block (PCB A).
  2. UPDATE Process State Transition the process state from 'Running' to 'Ready', 'Blocked', or another appropriate state.
  3. SELECT Next Ready Process The short-term scheduler picks the next eligible process (Process B) from the ready queue.
  4. LOAD Registers Restore the saved execution context from the new Process Control Block (PCB B) back into the CPU registers.
  5. RESUME Execution The CPU picks up exactly where Process B last left off and continues execution seamlessly.

The Dispatcher

The Dispatcher acts as the manager that formally transfers control of the CPU core to the specific process chosen by the short-term scheduler.

Its role bridges the gap between selection and actual execution, invoking the context switch mechanism shown in the central loop above.

Context Switching Overhead

  • No Useful Computation: The CPU performs pure administrative sorting during a switch; no actual user-space instructions or progress are processed during this window.
  • Efficiency Penalty: Frequent, rapid switching (due to poor time-slicing or heavy multi-tasking burdens) degrades overall system performance and CPU utilization efficiency.
  • Hardware Mitigation: Modern processing architectures implement dedicated hardware structures (like multiple register banks) to minimize the physical time required to swap state contexts.
