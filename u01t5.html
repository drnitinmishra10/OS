Unit 1: Introduction to Operating Systems

Lecture Notes by Dr. Nitin Mishra

1. Structure of an Operating System

The structural architecture of an OS dictates how internal software modules are organized and how they interact across system privilege boundaries. We explore three classic architectural paradigms:

A. Monolithic Architecture

The entire operating system runs as a single, large program operating completely within Kernel Mode. All services (scheduling, memory allocation, file management) are tightly integrated into a unified address space.

  • Mechanism: Applications trigger a system call, which shifts execution directly into the monolithic blob via internal function addresses.
  • Pros: Exceptional execution efficiency; there is virtually zero communication overhead because components interact via direct function calls.
  • Cons: Highly complex to maintain or expand. A single software fault or crash in a minor driver brings down the entire kernel framework.

B. Layered Architecture

The OS software is broken down into a hierarchy of distinct operational levels or layers. Layer 0 directly wraps the physical hardware, while the highest layer (Layer N) hosts the user interface interface routines.

  • Mechanism: Each layer can only invoke services provided by layers strictly underneath it. It hides implementation details from higher tiers.
  • Pros: Modular design facilitates straightforward debugging, code verification, and incremental system construction.
  • Cons: Difficult to cleanly define layer hierarchies. Passing data sequentially across multiple boundary boundaries degrades runtime efficiency.

C. Microkernel Architecture

This design actively strips all non-essential components out of kernel space, shifting subsystems (like file systems and device drivers) into independent User Space processes. The remaining microkernel handles only core primitives: IPC (Inter-Process Communication), basic memory management, and low-level scheduling.

  • Mechanism: Subsystems communicate with each other indirectly by passing message packages across the microkernel using IPC channels.
  • Pros: High extensibility and reliability. If a user-space file system crashes, the core kernel remains stable and functional.
  • Cons: Performance bottlenecks due to frequent context-switching overhead as messages traverse system spaces repeatedly.

2. Concept of a Virtual Machine (VM)

A Virtual Machine abstracts the underlying physical hardware of a single computer into several distinct computational environments. It creates an exact operational illusion that each guest OS has its own dedicated physical hardware resources.

The Hypervisor / Virtual Machine Monitor (VMM)

The core software layer responsible for this abstraction is the Hypervisor. It sits directly on the bare-metal hardware or host OS, managing hardware resources dynamically and isolating each VM environment safely from others.

  • Type 1 Hypervisor (Bare-Metal): Runs directly on the physical hardware architecture (e.g., VMware ESXi, Xen). Used heavily in corporate data centers.
  • Type 2 Hypervisor (Hosted): Runs on top of a standard host operating system (e.g., Oracle VirtualBox, VMware Workstation). Ideal for local development.

Key Technical Benefits

  • Total Isolation: Security is heavily enforced. If a guest OS suffers malware infection or critical failure, the host and neighboring VMs remain untouched.
  • Resource Consolidation: Allows multiple production servers running different operating systems (Windows, Linux) to maximize utilization on one physical machine.
  • Portability: Virtual environments can be saved as point-in-time snapshots or image files, enabling effortless migrations across physical hardware nodes.
