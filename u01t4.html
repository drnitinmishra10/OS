Unit 1: Introduction to Operating Systems

Lecture Notes by Dr. Nitin Mishra

1. Operating System Services

An operating system provides an environment for the execution of programs. It offers a set of core services that can be split into two main operational categories: functions that directly assist user programs, and functions designed to ensure efficient system operations.

Services for the User/Programmer:

  • User Interface (UI): Almost all operating systems have a user interface. This can be a Command-Line Interface (CLI), a Batch Interface, or a Graphical User Interface (GUI).
  • Program Execution: The system must be able to load a program into memory, execute it, run it to its conclusion, or terminate it normally or abnormally.
  • I/O Operations: A running program may require I/O, which may involve a file or an I/O device. For efficiency and security, users cannot control I/O devices directly; the OS must provide a means to do so.
  • File-System Manipulation: Programs need to read, write, create, delete, search, and list files or directories, as well as manage access permissions.
  • Communications: Processes often need to exchange information. This can happen between processes running on the same computer or between processes on different computers over a network (via shared memory or message passing).
  • Error Detection: The OS needs to be constantly aware of possible errors. It must check for hardware failures (like memory errors or power drops) and software bugs (like arithmetic overflow or illegal memory access) and take appropriate defensive action.

Services for System Efficiency:

  • Resource Allocation: When multiple jobs are running concurrently, resources (CPU cycles, main memory, storage, peripheral devices) must be allocated to each of them dynamically.
  • Accounting: Keeping track of which users use how much and what kinds of computer resources, useful for billing or system optimization.
  • Protection and Security: Ensuring that all access to system resources is controlled and isolated. Security requires authenticating users and protecting external I/O devices from unauthorized access.

2. System Calls

System Calls provide the essential interface between a running application program and the operating system kernel. They are the programmatic gatekeepers that allow user space applications to safely request privileged operations from kernel space.

The Dual-Mode Mechanism

To prevent user programs from accidentally or maliciously destroying the system, modern CPUs support at least two execution states controlled by a hardware mode bit:

  • User Mode (Mode bit = 1): The CPU executes code with restricted privileges. Attempting direct hardware access triggers a system trap.
  • Kernel/Supervisor Mode (Mode bit = 0): The CPU has complete, unrestricted access to all physical hardware instructions and memory spaces.
How a System Call Works:
1. User Application calls an API function (e.g., printf() or open()).
2. The API triggers a software trap/interrupt instruction.
3. Hardware switches from User Mode to Kernel Mode (mode bit becomes 0).
4. The OS indexes into a System Call Table to execute the requested kernel logic.
5. Once completed, the OS reverts the mode bit back to 1 and returns control to the program.

Types of System Calls

System calls can be grouped roughly into five major categories:

  1. Process Control: fork(), exec(), exit(), wait() — used to manage execution states, end running jobs, or create new parallel tasks.
  2. File Management: open(), read(), write(), close() — used to read, write, create, or navigate file hierarchies.
  3. Device Management: ioctl(), read(), write() — used to request, read from, or release hardware devices like disks or terminals.
  4. Information Maintenance: getpid(), time() — used to transfer metrics, time parameters, and identity data between the system and user programs.
  5. Communications: pipe(), shmget(), socket() — used to construct inter-process communication pipelines or open network sockets.
