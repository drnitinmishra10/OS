Unit 1: Introduction to Operating Systems

Lecture Notes by Dr. Nitin Mishra

1. What is an Operating System?

An Operating System (OS) is a system software that acts as an intermediary, resource manager, and control coordinator between the computer hardware and the end-user or application programs.

Core Abstract View:
User <---> Application Programs <---> Operating System <---> Hardware

Without an OS, every application developer would have to write low-level machine code to interact directly with the hard disk, CPU registers, and RAM, making computing highly inefficient and prone to system-wide crashes.

2. Dual Goals of an Operating System

An OS is designed with two fundamental, often competing objectives in mind:

  • Convenience (User View): To provide an intuitive, abstract, and user-friendly environment (via GUI or CLI) so that users can execute programs easily without worrying about low-level hardware configurations.
  • Efficiency (System View): To ensure that computer hardware resources—such as CPU cycles, memory blocks, and I/O devices—are utilized to their maximum potential with minimal idle time.

3. Fundamental Roles of an OS

Dr. Mishra breaks down the primary operational architecture of an OS into two structural identities:

A. Resource Allocator / Manager

The computer system consists of numerous hardware resources that must be divided dynamically among active processes. The OS handles:

  • CPU Management: Deciding which process gets the processor time and for how long (Scheduling).
  • Memory Management: Tracking every byte of primary memory and allocating/deallocating space dynamically.
  • Storage Management: Organizing structured file placement across physical tracks and sectors.
  • I/O Device Allocation: Resolving conflicting device requests from multiple processes.

B. The Control Program

The OS acts as an administrative manager regulating program executions to maintain safe system operations:

  • Prevention of Errors: Intercepting illegal commands or memory violations (like out-of-bounds array access hitting system memory).
  • Improper Use Protection: Ensuring user programs don't access access-restricted peripheral devices or corrupt other users' spaces.
  • Mode Isolation: Keeping user-level calculations separated from critical system kernel operations using hardware-driven mode-bit bit switches.

4. Key Takeaways for Examination

  • The OS is a Resource Manager mapping virtual logic to physical hardware.
  • It exists to resolve conflict safely and fairly when multiple tasks run simultaneously.
  • It represents a permanent control routine (the Kernel) running at all times alongside auxiliary system programs.
