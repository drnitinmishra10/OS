Introduction

An operating system manages hardware and software resources. One of its primary responsibilities is managing processes. Every application executed on a computer becomes one or more processes that compete for CPU time, memory, files, and I/O devices.

Definition of a Process

A process is a program in execution together with its execution context, allocated memory, CPU registers, open files, and other operating system resources.

Components of a Process
  • Program Code (Text Segment)
  • Data Segment (Global variables)
  • Heap (Dynamic memory)
  • Stack (Function calls and local variables)
  • Program Counter
  • CPU Registers

Process Relationships

Processes may exist independently or in parent-child relationships. A parent process can create child processes, which may execute concurrently and inherit selected resources.

Parent and Child Process

  • Parent creates child using system calls such as fork() in Linux.
  • Child receives a copy of the parent's execution context.
  • Parent may wait for the child to finish using wait().
pid_t pid = fork(); if(pid==0){ printf("Child Process"); }else{ printf("Parent Process"); }

Process Creation

  1. User requests program execution.
  2. Operating system allocates a Process Control Block.
  3. Memory is allocated.
  4. Executable is loaded.
  5. Process enters the Ready state.

Process Termination

  • Normal completion
  • Runtime error
  • Killed by operating system
  • Killed by another process

Five-State Process Model

StateDescription
NewProcess is being created.
ReadyWaiting for CPU.
RunningExecuting on CPU.
Waiting/BlockedWaiting for I/O or an event.
TerminatedExecution completed.

Seven-State Process Model

The extended model adds Ready Suspended and Blocked Suspended states to support swapping processes to secondary storage when memory is scarce.

Real-World Example

Opening a web browser creates a browser process. Opening multiple tabs often creates additional processes to improve security and stability.

Key Points

  • A program becomes a process when executed.
  • Each process has its own memory space and execution context.
  • Processes transition through different execution states.
  • Parent-child relationships simplify resource management.

Summary

This lecture introduced processes, program versus process, process components, parent-child relationships, creation and termination, and the five-state and seven-state process models. These concepts provide the foundation for understanding process scheduling in subsequent lectures.
